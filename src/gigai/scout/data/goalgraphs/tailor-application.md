# Tailor an application

First read the [shared handoff rules](README.md). Require a selected posting,
candidate evidence and the requested output: resume, cover letter, or both.
Role research is optional. Preserve the original resume and all prior drafts.

Map posting requirements to exact supplied evidence. Ask focused questions for
material gaps: for example, ask about harness engineering instead of claiming
the user has done it. Record missing, answered, declined and not-applicable
separately. Do not invent employers, skills, dates, metrics, achievements,
authorization or sponsorship. User assertions remain user-reported evidence.

Create exactly the requested documents, a requirement-to-evidence matrix, gap
report and inspectable checks. Bind every claim and check to the selected input
and output revisions. New answers may require a successor Run and revised draft.

ATS-oriented checks are advisory: plain-text structure/headings, required
contact-field presence without echoing values, declared length bounds,
requirement coverage, unsupported claims, placeholders and cover-letter
job/company specificity. Record rule/version, input digests, findings, severity
and evidence. A lexical match is `term_present`, not proof of competence.
Semantic checks are agent-reported unless independently reviewed. Never invent
an employer ATS score, hiring guarantee or keyword-stuffing recommendation.

Hand off Markdown and exact-byte JSON sidecars for the requested documents and
checks. Let the user select a final revision. A final resume is not an applied
job; ask what they want to do next without changing application state.
