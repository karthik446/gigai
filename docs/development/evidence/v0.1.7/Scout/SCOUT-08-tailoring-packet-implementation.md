# SCOUT-08 — Pure tailoring packet candidate

Status: implemented in the Luna-owned candidate lane on 2026-09-10.  This is
an in-memory renderer and strict validator; it is not a Plan/Run caller, a
journal publisher, a provider invocation, an ATS service, or a source
materializer.

The module exposes `build_tailoring_packet` (with the discoverable aliases
`render_tailoring_packet` and `validate_rendered_packet`) and the immutable
`TailoringPacket`/`TailoringPacketError` types.  A request supplies exactly
`resume`, `cover_letter`, or both, plus closed source-role bindings,
requirement matrix, claim/evidence rows, gaps and questions.  The builder
returns only the requested document byte map and one canonical sidecar; it
does not manufacture a third output.

## Binding and safety behavior

The sidecar binds `project_id`, `gig_id`, Gig version, the fixed
`tailor-application` graph selector and graph version, Run ID, and the exact
selected normalized input envelopes.  Each posting/candidate source role
names an input index and an exact supplied byte map; each included requirement
or candidate fact claim carries a source role and byte start/end span with a
digest of the exact quoted bytes.  Source artifacts are bounded, canonical
base64 copies for later journal adapters; source paths are never opened and
source text is never interpreted as instructions.

Candidate claim judgments are caller-reported data, not semantic proof.  A
supported claim must have candidate evidence; unsupported/conflicted claims
are marked `included: false` and receive deterministic gap/question entries.
A conservative lexical gate keeps claims mentioning harness engineering or
explicit percentage metrics out of positive facts unless a future contract
provides a separately reviewed semantic path.  Posting text is accepted only
for posting spans and cannot serve as candidate evidence.  The packet carries
explicit limits that semantic factuality is external-agent reported, lexical
matches are not semantic proof, and no hiring/ATS score is produced.

Markdown is supplied as UTF-8 bytes and is preserved byte-for-byte.  NUL and
other unsafe control characters, malformed UTF-8, oversized documents, and
`javascript:`, `data:`, or `vbscript:` links are refused.  Existing
`gigai.scout_checks.check_document` is run against each exact requested draft;
its advisory report is stored with the document digest and regenerated by
validation.  The sidecar has a canonical `packet_sha256` over all fields
except that digest, and validation rebuilds the entire packet, so changing a
draft or any selected input/source bytes cannot reuse old checks.

## Remaining integration gates

The schema is intentionally not added here to central validator/hash/golden
inventories.  The coordinator must register the package resource and decide
whether the source inventory accepts capability `...075`; the Plan/Run caller
must authenticate committed `scout_inputs` envelopes and persist the returned
Markdown/sidecar through the generic external recording channel.  Semantic
factuality, requirement judgment, experience-question continuation, user
selection/finalization, and later application recording remain external
caller responsibilities.  This packet is not evidence of source promotion,
provider execution, application submission, or complete SCOUT-08 acceptance.
