# G31 — v0.1.6 Readiness and Human UAT

- Status: Active — release-candidate verification underway
- Type: Release-lane readiness and human-UAT goal; not an alpha declaration
- Depends on: G30 completion audit, G27/G28 runtime evidence, G29 findings where applicable, and G12 release mechanics
- Unblocks: the explicit v0.1.6 release decision and later G25 alpha review

## Outcome

G31 decides whether GigAI is ready to publish v0.1.6 as a useful operator release. It evaluates the complete browser-first setup and create experience, real Codex/Claude CLI support, supported API-provider onboarding, local folder ownership, durable SQLite/workpad state, and representative Gig workflows.

G31 does not infer release authority from passing unit tests. It requires machine evidence, installed replay, behavioral evaluation, and a human UAT session with sanitized findings.

## Contract gate

Before release evidence begins, G30's completion audit and terminal handoff must be accepted. The release candidate must be built from a merged commit, tested from a fresh wheel, and published only through the owner-controlled exact-tag workflow. No local tag or direct main-branch release is authorized.

## Required UAT surfaces

- Fresh setup with a user-selected GigAI folder;
- rerun setup without losing existing providers or workpads;
- Codex and Claude selection, readiness, default-model behavior, and auth failure handling;
- OpenAI/OpenRouter credential-reference configuration without secret leakage;
- `gigai create tailor-resume-for-job` with optional resume and cover-letter references and adaptive follow-up questions;
- proposal build, revision, rejection, explicit approval, and no-target-effect behavior;
- SQLite interview trace, workpad journal, projection/index inspection, and recovery after interruption;
- reinstall/reopen from the released wheel;
- representative review-and-verify and improvement flows.

## Acceptance criteria

1. Full unit/integration/installed-E2E/behavioral-eval suites pass with separate reports and no hidden test-tier substitution.
2. G30's real CLI and credential-boundary evidence is reproduced from the release candidate.
3. Fresh install and upgrade from the preceding published version succeed.
4. The human operator records expected, surprising, blocked, and unsafe outcomes for each UAT scenario; raw transcripts and secrets remain local.
5. SQLite, workpad, journal, active-version, and proposal authorities are inspected and reconciled without destructive projection rebuilds.
6. Setup rerun, browser-session interruption, CLI unavailability, missing API credential, malformed provider output, and stale target cases fail closed.
7. External `CHANGELOG.md` contains capabilities only; internal changelog records implementation details and review corrections.
8. The exact-tag release workflow produces and verifies the v0.1.6 artifact from merged main, including installed schema/resource checks.
9. Completion audit and terminal handoff state whether v0.1.6 is publishable; no alpha claim is made until G25's release-lane criteria are met.

## Evidence and stop boundary

Evidence belongs under `docs/development/evidence/phase-5/G31/`, with raw UAT material kept outside Git. Stop if the ordinary setup/create flow requires implementation flags, either real CLI cannot be configured and exercised, a credential or durable trace leaks secret values, reinstall/reopen loses authority, or release artifacts cannot be reproduced from an exact merged tag.
