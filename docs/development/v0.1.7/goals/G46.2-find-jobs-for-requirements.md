# G46.2 — Job Search Lifecycle Gig v2: `find-jobs-for-requirements`

**Version:** v0.1.7
**Status:** Proposed — contract defined; not activated
**Parent:** G46 Job Search Lifecycle Gig family
**Depends on:** G44, G45.2, G46, and G46.1
**Delivery:** private manual foreground graph; not a catalog entry or scheduler

## Outcome

G46.2 proves an explicitly operator-approved v2 of the private
`job-search-lifecycle` Gig. v2 retains the v1 `tailor-application` graph and
adds one independently selectable `find-jobs-for-requirements` graph.

```text
explicit requirements profile + approved source
  -> sealed foreground Find Plan
  -> direct-confirmed bounded source read
  -> private, provenance-bound job leads and report
  -> operator selects one lead, or stops
```

The graph finds leads that match declared requirements. It does not promise
market coverage, hiring outcomes, application eligibility, or that any lead is
current beyond its recorded retrieval/as-of time.

## Inputs, effects, and outputs

The Find graph accepts exactly one sealed G45.2 `job_search_requirements`
input and one source-registry entry. The requirements profile may contain only
the approved source query fields plus local filtering preferences: target role
or keywords, location/remote preference, seniority, employment type, salary
constraint when supported, and explicitly named include/exclude criteria. The
operator sees the exact outbound subset before the Plan is sealed. A résumé,
private work history, or prior Tailor output is never an outbound query or
implicit input.

Its only external effect is the bounded G45.2 network read through the selected
source adapter. It has no target-repository write, provider-directed source
fetch, browser capability, credential, external write, schedule, or submission
effect. Source text is untrusted data and cannot override this contract.

Every terminal Run writes private artifacts:

- raw response snapshots and normalized lead records from G45.2;
- `job-leads.json`, `job-leads.md`, and optional rebuildable
  `job-leads.html` projection;
- `job-search-result.schema.json` manifest with source policy, query-preview
  digest, retrieval/as-of time, lead references, duplicate evidence, terminal
  status, and diagnostics; and
- a requirements-to-lead relevance map citing exact requirements and source
  fields for each result.

HTML is a static Run artifact, not a web server or new authority surface.

## Relevance and quality rules

Relevance is an explanation of the relationship between declared requirements
and source fields, not a recommendation, factual claim about the operator, or
inference about application status. Every surfaced reason cites both a
requirements locator and a normalized/source-field locator. Missing fields are
displayed as unknown; they are never invented or silently scored as matches.

Within-Run deduplication follows G45.2's identity rule. Cross-Run comparison is
an explicit report operation only in v0.1.7; the graph has no mutable current
lead list, saved list, applied list, or automatic suppression.

The evaluation pack freezes sanitized structured source fixtures, requirements
profiles, expected normalization/identity outcomes, relevance-label rubric,
no-match/source-failure cases, and held-out split before any provider-backed
quality execution. It measures provenance completeness, source-policy
compliance, deterministic deduplication, relevance explanation correctness,
latency, source/model cost where applicable, failure rate, and rebuildability.

## Lifecycle and handoff

G46.2 creates an ordinary Gig amendment from v1 to v2. The operator inspects
the Graph Set difference, source effect, evaluation evidence, and profile/budget
changes, then explicitly approves v2. Existing v1 Tailor Runs stay attributable
to v1 and reproducible.

The manual execution path is:

```text
gigai job-requirements add --source SOURCE_ID --stdin
  -> gigai run-plan create --gig GIG_ID --graph find-jobs-for-requirements
       --source SOURCE_ID --input REQUIREMENTS_INPUT_ID
  -> inspect exact query preview and PLAN_ID
  -> gigai run --plan PLAN_ID --confirm
  -> inspect private lead report
```

After a successful Find Run, `gigai job-lead select LEAD_ID --gig GIG_ID
--confirm` creates the G45.2 lead-input binding. The operator must then create
a separate Tailor Plan naming that binding/input and separately run
`gigai run --plan PLAN_ID --confirm`. There is no automatic Find-to-Tailor
journey in v0.1.7.

## Acceptance evidence and stop conditions

Acceptance proves the v2 graph-addition lineage, independent graph selection,
manual source run, source provenance, lead selection binding, subsequent
Tailor Plan binding, and historical v1 replay. It includes successful search,
no matching jobs, stale results, malformed content, duplicate leads, source
failure, rate exhaustion, operator cancellation, unavailable source adapter,
and refusal to use an undeclared source.

Stop if a source read occurs before direct Run consent, a lead creates or starts
a Tailor Run automatically, private résumé material leaves the selected local
boundary, a provider chooses a URL/source, application state is inferred, or a
network/source failure silently falls back.
