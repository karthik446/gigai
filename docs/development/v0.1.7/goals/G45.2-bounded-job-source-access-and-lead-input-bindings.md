# G45.2 — Bounded Job-Source Access and Lead Input Bindings

**Version:** v0.1.7
**Status:** Proposed — contract defined; not activated
**Depends on:** G43.2, G45, and S45.2 Adopt decision
**First consumer:** G46.2 `find-jobs-for-requirements`

## Outcome

G45.2 adds one reviewed adapter for operator-configured, unauthenticated,
public, structured job sources. It makes a bounded foreground network read
rebuildable and lets an operator explicitly turn one immutable job lead into a
Tailor-eligible job-description input.

```text
requirements profile + allowed source
  -> sealed source query preview + direct Run confirmation
  -> raw response snapshot + normalized private leads
  -> operator selects LEAD_ID
  -> idempotent lead-to-job-description binding
```

It is not a generic crawler, browser, search engine, credential store, job-board
login, application tracker, scheduler, or provider-directed fetch facility.

## Source registry and adapter boundary

`job-source-registry.schema.json` has schema ID
`urn:gigai:schema:job-source-registry:1`. A strict registry entry has
`source_id`, adapter/version, allowed HTTPS origins and URL shapes, redirect
policy, permitted outbound query fields, request/response ceilings,
source-specific terms/rate policy, normalized-field mapping, lead identity
rule, and fixture/replay identity. It contains no cookies, credentials,
arbitrary URL templates, or private project values.

S45.2 selects exactly one initial source class and adapter. Until it records an
Adopt decision, every attempted G45.2 operation fails with
`job_source_not_approved`. There is no source fallback.

The adapter may issue at most 10 HTTPS requests per Run, with no redirects, a
10-second connect/read timeout per request, 2 MiB maximum response bytes per
request, 10 MiB aggregate response bytes, and 200 normalized leads. The source
registry may lower these ceilings but never raise them. Every DNS result and
connected address must be public; loopback, link-local, private, multicast,
unspecified, and carrier-grade NAT ranges are refused before connection.
HTTPS origin, port, path, and query keys must match the source entry exactly.

A source request is a graph-declared deterministic network-read effect, not a
model tool call. It has the independent `max_source_requests` ceiling above;
it does not alter G43's zero model-tool-call default or let a model invoke the
adapter. The Find Graph requires the source-specific capability named by its
registry entry; the sealed Plan records that capability, source-effect ceiling,
and selected adapter before the Run's direct confirmation.

The adapter sends only the source entry's declared query fields after showing
their exact values in the sealed Plan preview. It never sends a résumé, private
work history, credential, cookie, local path, transcript, or model-generated
URL. Fetched text is untrusted data: it cannot change effects, tools, source
selection, prompts, graph selection, or later commands.

## CLI contract

G45.2 adds only explicit, bounded surfaces:

```text
gigai job-source list [--json]
gigai job-source show SOURCE_ID [--json]
gigai job-requirements add --source SOURCE_ID (--file PATH | --stdin)
  [--label LABEL] [--target PATH]
gigai job-lead select LEAD_ID --gig GIG_ID --confirm [--target PATH]
```

Listing/showing a source performs no network request. Adding requirements
writes only a private immutable input record and performs no model or source
call. `run-plan create` receives the requirements-input ID and source ID
explicitly, renders the outbound-query preview in the sealed Plan, and still
does not fetch. Only the later direct-confirmed Find Run may execute the
adapter. Human/JSON output follows the existing safe-label/ID/digest boundary.

## Immutable source and lead records

Raw source responses are private workpad artifacts. Their normalized output is
`job-lead-record.schema.json`, schema ID `urn:gigai:schema:job-lead-record:1`,
stored under `runs/<run_id>/job-leads/lead_<uuidv4>/lead.json`. A record
requires `schema_version`, `lead_id`, `run_id`, `gig_id`, `graph_id`,
`source_id`, `source_adapter_version`, `source_url`, `retrieved_at`,
`as_of`, `raw_response`, `normalized_job_description`, `identity_key`,
`relevance`, and `created_at`.

`raw_response` and `normalized_job_description` are artifact references. The
normalized description is a sealed private text snapshot; it does not overwrite
or reinterpret the raw response. `identity_key` is derived only from
source-stable public identifiers or a canonical public-field tuple defined by
the source registry. `relevance` contains only requirement-reference locators,
source-field locators, and a bounded explanation; it does not claim the
operator is qualified.

Within one Run, equal `identity_key` values deduplicate deterministically: the
lowest canonical source URL wins, remaining candidates appear only as
deduplication evidence, and no lead is silently merged across Runs. A failed,
empty, malformed, stale, or rate-limited response produces an honest terminal
result and provenance; it is never substituted with another source or a search
engine.

G45.2 also adds `urn:gigai:schema:run-input-record:2` without changing G45's
historical v1 record. v2 accepts sealed `job_search_requirements` inputs from
explicit operator paste or local text files, and sealed `job_description`
inputs with origin `lead_selection`. A requirements record contains only the
typed query/filter fields allowed by its selected source entry; no résumé,
private history, arbitrary notes, or undeclared query key is accepted. A v2
record has the same project, digest, snapshot, privacy, and immutable-record
invariants as G45 v1, plus its exact origin and, for lead selection, a binding
lead reference and normalized snapshot digest. The enclosing lead-input binding
records the input-record reference; the input record does not refer back to its
enclosing binding.

## Explicit lead selection and input binding

`gigai job-lead select LEAD_ID --gig GIG_ID --confirm` is the only operation
that creates a Tailor-eligible lead binding. It verifies the lead belongs to
the selected Job Search Lifecycle Gig and an approved
`find-jobs-for-requirements` Run, then writes a strict
`lead-input-binding.schema.json` artifact with schema ID
`urn:gigai:schema:lead-input-binding:1`.

The binding requires `schema_version`, `binding_id`, `project_id`, `gig_id`,
`lead`, `lead_snapshot`, `job_description_input`, `created_by`, and
`created_at`. `binding_id` matches `lead_binding_<uuidv4>`.
`lead_snapshot` is the exact normalized-job-description reference from the lead.
`job_description_input` is a new private
`urn:gigai:schema:run-input-record:2` record with kind `job_description` and
origin `lead_selection`; it records the exact lead reference and the same
snapshot digest. The enclosing binding then links that input record to its
lead-selection authority, avoiding a circular artifact reference. v1 G45
local-file/operator-paste inputs remain valid and unchanged.

The binding idempotency key is project ID, Gig ID, `lead_id`, and normalized
job-description digest. Repeating selection returns the existing binding. A
changed lead snapshot creates a new binding and a new input record. The command
writes private workpad evidence only: it does not start tailoring, allocate a
Run, invoke a model, grant source/provider permission, or alter application
state.

## Plan, consent, and privacy boundary

A Find Plan seals the requirements input, source-registry entry, exact outbound
query preview, adapter version, request ceilings, and source-policy reference.
Direct `gigai run --confirm` is the only authorization to execute its network
read. A Tailor Plan may consume a lead-derived job-description input only when
the operator explicitly names the binding/input ID; it seals the binding, lead,
and exact job-description digest as sources. It has its own direct Run consent.

Human and JSON output may show source IDs, safe public URL labels, retrieval
time, lead IDs, counts, and bounded relevance reasons. Raw responses, private
requirements, local paths, cookies, credentials, and private source artifacts
remain out of portable packages, catalog fixtures, committed evidence, and
diagnostics. Sanitized fixtures contain no live applicant or job-source data.

## Acceptance evidence

G45.2 requires deterministic adapter fixtures plus one operator-consented live
source execution after S45.2 Adopt. It proves:

- unapproved/unsupported source, malformed registry, non-HTTPS origin,
  redirect, SSRF/private address, illegal path/query, timeout, response-size,
  request-count, and rate/terms refusal all fail closed;
- query preview lists exactly the outbound fields and excludes private résumé
  or conversation data;
- raw and normalized snapshots, URL/source identity, adapter version, retrieval
  time, response digest, and as-of time are reconstructable;
- malformed source content, stale results, no matches, duplicate leads, source
  failure, rate exhaustion, and operator cancellation have typed terminal
  outcomes with no fallback;
- within-Run deduplication is deterministic; and
- lead selection is direct-confirmed, idempotent, digest-bound, does not start
  tailoring, and creates an input binding consumable only by an explicitly
  sealed Tailor Plan.

## Out of scope and stop conditions

Out of scope: arbitrary URLs, web search, HTML scraping, browser automation,
JavaScript, login/cookies, job application submission, outreach, mutable
saved/applied states, cross-Run lead suppression, schedules, and provider-led
source selection.

Stop if an undeclared origin is reached, a private address can be contacted, a
source result is treated as instruction, a lead is selected without direct
operator confirmation, a binding starts tailoring or grants consent, source
data enters a package/committed evidence, or a failure triggers fallback.
