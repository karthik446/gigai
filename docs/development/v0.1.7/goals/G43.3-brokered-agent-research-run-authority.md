# G43.3 — Brokered Agent Research Run Authority

**Version:** v0.1.7
**Status:** Proposed — pending S43.3 authority-focused Adopt and incomplete G43.1/G43.2 prerequisites
**Depends on:** completed G43, completed G43.2, and S43.3 authority-focused Adopt decision
**Unblocks:** G45.2 only after implementation and acceptance evidence

The historical S43.3 closed-runtime inquiry concluded Reject for the current
CLIs. Its [authority-focused amendment](../../evidence/v0.1.7/S43.3/authority-focused-amendment.md)
preserves that result while defining the current, narrower gate. This Goal may
use those CLIs only after the amended gate reaches Adopt.

## Outcome

G43.3 adds a generic, additive authority path for an agent-driven research Run.
It does not change G43's completed review profiles. It introduces a new
`run-plan:2` contract and the new `research-standard@1` profile. Participants
are untrusted public-research suggestion sources; only GigAI may create a
Plan-bound broker action, evidence record, or lineage edge.

```text
approved Gig + selected graph + sealed research Run Plan v2
  -> direct Run confirmation
  -> GigAI-generated public brief -> primary research suggestion
  -> GigAI-owned broker action lifecycle
  -> GigAI-generated public evidence view + public brief
  -> independent verification suggestion
  -> deterministic resolve and domain-owned outcome
```

`run-plan:1`, the `focused@1`, `standard@1`, `deep@1`, and `var@1` profiles,
and every historical v1 byte retain their exact existing semantics. In
particular, `standard@1` continues to authorize zero tool calls and its
existing four-phase review vocabulary. A v1 reader never projects itself as a
research Plan.

## Run Plan v2 and research profile

`run-plan-v2.schema.json` has schema ID `urn:gigai:schema:run-plan:2`. It is an
additive artifact with a new writer/reader/validator; it does not loosen v1
validation. Its required v2 fields include the existing sealed identity,
source, effect, budget, and consent bindings plus `research_contract`,
`broker`, `research_budget`, `participant_brief_policy`,
`participant_authentication_bindings`, and `participant_runtime_disclosure`. It
permits the profile ID `research-standard` at profile version `1` only.

`marker-probe-record.schema.json` has schema ID
`urn:gigai:schema:marker-probe-record:1`. GigAI writes this strict private
record at `adapter-probes/marker_<uuidv4>.json` only for a direct,
operator-confirmed S43.3 marker probe. It requires `schema_version`, `probe_id`,
`target`, `adapter_identity`, `channel_configuration_ref`,
`channel_configuration_sha256`, `operator_confirmation`, `marker_sha256`,
`reservation`, `actual_usage`, `reconciliation`, `terminal_state`,
`terminal_code`, `created_at`, `started_at`, and `completed_at`; `probe_id`
matches `marker_probe_<uuidv4>`. `operator_confirmation` is exactly a
`{ source: "direct_cli_confirm", command_kind: "models_probe_public_marker",
confirmed_at: RFC3339 }` object. `reservation` is exactly `{ model_calls: 1,
max_tokens: positive integer, max_cost_usd: positive decimal }`; its values are
the operator-supplied finite limits. `actual_usage` and `reconciliation` use
the S43.3 sealed no-report algebra.

`terminal_state` is exactly `succeeded`, `refused`, `failed`, or `cancelled`.
`terminal_code` is null exactly on `succeeded`; otherwise it is one of
`marker_probe_confirmation_required`, `marker_probe_budget_invalid`,
`marker_probe_adapter_unavailable`, `marker_probe_authentication_unavailable`,
`marker_probe_marker_mismatch`, `marker_probe_timeout`,
`marker_probe_usage_unreconciled`, or `marker_probe_cancelled`. The record
contains neither a credential, host path, raw prompt, raw marker, nor raw
provider output. A proof's `marker_evidence` must reference one `succeeded`
record whose target, executable/adapter identity, channel-configuration
reference/digest, reservation, and reconciled usage all match the proof.

`participant-authentication-channel-proof.schema.json` has schema ID
`urn:gigai:schema:participant-authentication-channel-proof:1`. GigAI writes a
strict private proof at `adapter-proofs/auth_<uuidv4>.json` only after the
S43.3 exact-adapter marker invocation succeeds. It requires `schema_version`,
`proof_id`, `target`, `adapter_identity`, `channel_kind`,
`credential_reference_kind`, `channel_configuration_ref`,
`channel_configuration_sha256`, `home_xdg_inheritance`, `marker_evidence`,
`issued_at`, and `expires_at`; `proof_id` matches
`participant_auth_proof_<uuidv4>`. `adapter_identity` binds the resolved
executable digest and reported version. `home_xdg_inheritance` is exactly
`false`; `channel_configuration_ref` is an exact reference to GigAI's
non-secret authentication-channel configuration projection, whose digest must
equal `channel_configuration_sha256`; and `marker_evidence` is an exact safe
artifact reference for the bounded public marker invocation. The artifact
contains no credential, host path, or raw prompt/output. `expires_at` is
mandatory, but expiry alone is not validity: a changed current configuration
projection or digest invalidates the proof immediately.

`participant_authentication_bindings` is the ordered array of exactly
`{ participant_id, proof_ref }` objects for the Plan's participants. The proof
is reusable pre-Run target/adapter/channel evidence and has no participant
identity. Each binding must match its Plan participant's target and adapter,
while the proof must match the current non-secret channel-configuration
projection/digest and current time. Missing, expired, foreign, duplicate, or
mismatched binding/proof fails `participant_authentication_proof_invalid`
before consent preview or Run allocation. Plan construction may select and
validate an existing proof; it cannot initiate a marker probe.

Immediately before **every** participant invocation, GigAI revalidates the
bound proof against the Plan participant's target, the freshly resolved
executable digest/adapter identity, the current authentication-channel
configuration reference/digest, and `expires_at`. A post-consent expiry,
executable change, configuration change, missing marker record, or any
mismatch fails `participant_authentication_proof_invalid` before prompt
assembly or process launch. It cannot refresh the proof or invoke a marker
probe implicitly; the Run ends at its defined refusal/blocked outcome.

`participant_runtime_disclosure` is a required sealed v2 object with exactly
`mode`, `participant_ids`, `supplied_context`, `accounting_scope`,
`native_activity_observability`, and `private_input_rule`. Its values are
respectively `unrestricted_public_suggestion_sources`, the Plan's ordered
participant IDs, `sealed_public_briefs_only`,
`gigai_started_invocations_and_broker_events_only`,
`not_observed_or_accounted`, and `restricted_adapter_required`. A v2 Plan with
a different, missing, or participant-mismatched disclosure is invalid.

`gigai run --plan PLAN_ID --confirm` must render this exact sealed disclosure
in its consent preview before the confirmation prompt. The preview plainly says
that participants are unrestricted public-suggestion sources, GigAI accounts
only for invocations it starts and broker actions it performs, and native CLI
activity it cannot observe is not accounted. The existing consent record binds
the exact Plan digest, so it binds this disclosure without creating a second
consent authority. A changed disclosure requires a new Plan, preview, and
direct confirmation; a missing/mismatched preview fails
`run_plan_runtime_disclosure_mismatch` before Run allocation.

`research-participant-brief.schema.json` has schema ID
`urn:gigai:schema:research-participant-brief:1`. GigAI writes one strict brief
after `run_started` and before each unrestricted invocation at
`runs/<run_id>/research/briefs/brief_<uuidv4>.json`. It requires
`schema_version`, `brief_id`, `run_id`, `run_plan`, `participant_id`, `role`,
`phase`, `public_payload`, `public_field_derivations`, `evidence_views`,
`content_sha256`, and `created_at`; `brief_id` matches
`research_brief_<uuidv4>`. `content_sha256` is the SHA-256 digest of the
canonical UTF-8 JSON encoding of the subordinate `public_payload` value only;
it is not a self-referential digest of the enclosing brief. The Plan pins the
fixed public-only prompt template, and the adapter receives only that template
plus `public_payload`.

Every payload field is derived from the sealed `participant_brief_policy`.
`evidence_views` is an ordered artifact-reference array whose members must be
valid `public-research-evidence-view:1` records from the same Run and Plan;
their public payloads and opaque handles are copied into this brief's
`public_payload`, and the artifact references themselves are not prompt input.
Those copied fields are the only provider-derived material that a subsequent
participant may receive. Private/local-only source references, raw provider
responses, undeclared text, and host configuration are invalid. The Plan seals
the policy, not a pre-Run brief, so Run-ID allocation and historical Plan bytes
remain unchanged.

An unrestricted invocation is disclosure-isolated: GigAI supplies a newly
created empty working root and fresh empty `HOME`, `CODEX_HOME`,
`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, and `TMPDIR` descendants,
uses a fixed locale/process allowlist and a previously resolved executable
path, and supplies no inherited `PATH`, GigAI-home/workpad path, repository
path, agent instruction, memory, cache, or credential. Provider authentication
must use a separately proven adapter channel. This does not assert that a
native CLI is physically confined; it proves only that GigAI does not disclose
ambient local state through its invocation boundary.

`research-standard@1` has exactly two provider participants and one
deterministic resolver:

| Participant/phase | Count | Role | Independence rule |
|---|---:|---|---|
| `research` | 1 | `researcher` | primary group |
| `research_verify` | 1 | `research_verifier` | different group and target from researcher |
| `resolve` | 0 provider | GigAI deterministic resolver | no provider target |

The phase order is exactly `research`, `research_verify`, `resolve`. The
researcher may make non-authoritative action suggestions; the research verifier
may make its own independent suggestions and validates only sealed
broker-generated public evidence views. Neither role may self-verify the sole
evidence it produced.
Disagreement, unavailable verification, a malformed evidence record, or a missing required independent
action ends at `resolve` as a domain-visible inconclusive outcome; it does not
silently add an adjudicator or reuse a target.

The profile's immutable maximum envelope is 80 provider model calls, 40 broker
actions, 100,000 provider tokens, USD 20.00 aggregate reserved cost, 16 MiB
aggregate broker-response bytes, 30 minutes wall time, one pass, and serial
broker dispatch. A graph/policy may lower any ceiling but cannot raise it. A
sealed v2 Plan must additionally allocate finite non-zero or zero limits to
each participant and action type; the participant allocations sum within the
profile envelope. There are no defaults, overflow pools, or implicit retries.

Every provider invocation GigAI starts is one reserved model call, including
one that emits a suggestion, receives a broker result, terminates, fails, or is
cancelled. A broker action is separately counted. GigAI records those
invocations and its broker events, but makes no claim about internal CLI turns
or native actions it cannot observe. The Plan rejects a budget that cannot
reserve every GigAI-started provider invocation and broker action before Run
start.

## GigAI-owned broker lifecycle

G43.3 defines the generic broker protocol; a later provider/domain contract
defines the allowed action names and canonical private payload.

`public-research-evidence-view.schema.json` has schema ID
`urn:gigai:schema:public-research-evidence-view:1`. Only GigAI may construct
this private lineage-bearing record after a broker response passes the sealed
provider-validation and sanitization rules. Its `public_payload` is the
disclosure-safe projection; the enclosing artifact reference stays private. It is stored at
`runs/<run_id>/research/evidence-views/view_<uuidv4>.json` and requires
`schema_version`, `view_id`, `run_id`, `run_plan`, `source_actions`,
`public_payload`, `public_payload_sha256`, `opaque_result_handles`,
`field_derivations`, and `created_at`; `view_id` matches
`research_evidence_view_<uuidv4>`. `source_actions` is an ordered exact
broker-action reference array. `public_payload_sha256` is the SHA-256 digest
of canonical UTF-8 JSON `public_payload`. `opaque_result_handles` consists of
GigAI-minted `research_result_<uuidv4>` handles, each bound privately to one
source-action reference and result ordinal, never a provider result identifier.
The artifact retains exact broker lineage and policy-approved public fields but
excludes raw provider response bytes, raw URLs, raw citations, credentials, and
undeclared fields. Only its `public_payload` and opaque handles may be copied
into a later participant brief.

`research-action-suggestion.schema.json` has schema ID
`urn:gigai:schema:research-action-suggestion:1`. GigAI, never a participant,
constructs the record from one captured adapter output. It requires
`schema_version`, `suggestion_id`, `run_id`, `run_plan`, `participant`,
`phase`, `invocation`, `public_brief`, `raw_output`, `candidate_action`, and
`created_at`; `suggestion_id` matches `research_suggestion_<uuidv4>`. The
participant cannot choose any of those bindings. `candidate_action` is
exactly `suggested_action_type`, `public_field_keys`,
`referenced_result_handles`, and nullable `rationale`. The type must be
permitted by the Plan, every key must exist in the sealed public brief, and
every referenced handle must be exposed by an evidence view in that same brief;
rationale is non-authoritative text. A handle is an untrusted nomination, not
a provider identifier. URLs, citations, provider results, and claims inside the
raw output are suggestions rather than evidence or fetch instructions.
The artifact path is exactly
`runs/<run_id>/research/suggestions/suggestion_<uuidv4>.json`; its identity,
participant/role/phase bindings, and raw-output reference are GigAI-generated.

`broker-action-request.schema.json` has schema ID
`urn:gigai:schema:broker-action-request:1`. GigAI constructs it only after a
suggestion passes validation. It requires `schema_version`, `request_id`,
`run_id`, `run_plan`, `participant_id`, `role`, `phase`, `suggestion`,
`public_brief`, `evidence_views`, `result_handles`, `action_type`,
`action_ordinal`, `payload`, `payload_digest`, `idempotency_key`, and
`requested_at`. `request_id` matches
`broker_request_<uuidv4>`; the idempotency key is canonical Plan digest,
GigAI-assigned participant ID, phase, action ordinal, action type, and payload
digest. A participant does not have a broker credential, workpad-write
capability, or authority to construct a request.

Before dispatch, GigAI validates its own Plan/Run bindings, assigned
participant/role/phase, public brief, evidence views, serial ordinal,
capability/action type, policy, payload derivation, and remaining reservations.
Every requested result handle must be exposed in the brief, resolve to a
GigAI-minted same-Run/Plan action result, satisfy the adopted policy's lineage
rule, and be converted by GigAI into the provider-specific selector. A handle,
URL, citation, or raw provider result from a participant is never a direct
provider selector. GigAI writes an ordered broker event and reserves the
action's count, worst-case cost, response bytes, and wall time. Only then may
it dispatch one action.

`broker-action-event.schema.json` has schema ID
`urn:gigai:schema:broker-action-event:1`. It requires `schema_version`,
`event_id`, `run_id`, `request`, `sequence`, `state`, `reservation`,
`dispatch_attempts`, `response_ref`, `actual_usage`, `reconciliation`,
`terminal_code`, and `created_at`. `state` is exactly `reserved`, `dispatched`,
`completed`, `failed`, `cancelled`, or `rejected`; its semantic transitions are
strictly forward. The event does not expose a credential value or auth header.

The identical idempotency key returns the recorded terminal event and never
dispatches again. A distinct retry is a new action ordinal and consumes a new
reservation. A timeout, cancellation, or transport failure after dispatch
remains one attempted action: it reconciles known actuals, reserves the
unknown portion under the sealed no-report rule, and cannot be hidden as a
free retry. Cancellation prohibits new model turns and broker actions after its
ordered terminal event.

## Accounting, evidence, and authority

The Plan seals the S43.3 authority-focused evidence, broker implementation
identity, allowed capability/policy reference, role/target assignments,
per-role/action budgets, reservation table, no-report rule, every selected
input, and every participant public-brief disclosure rule. Provider or tool
facts are not inferred from discovery output or participant claims.

Every GigAI-started provider invocation and GigAI broker event is durable
private Run evidence with a monotonic Run sequence. A projection may redact
content but must preserve GigAI-generated IDs, ordering, participant/role,
action type, reservation, actual/reconciled usage, and terminal code. GigAI
does not claim to observe internal CLI turns or native actions. Any such output
is untrusted and cannot become authoritative evidence; an unreported actual
that violates the sealed no-report rule, a cross-participant suggestion, or an
action after cancellation fails the Run closed.

Direct operator `gigai run --confirm` is the only action that starts this
lifecycle. A model output, request payload, proposal, environment default,
previous confirmation, or replay cannot create or replay Run consent.

## Acceptance evidence and stop conditions

G43.3 is complete only when it proves:

- v1 Run Plans, readers, bytes, profiles, and `standard@1` behavior remain
  unchanged, while v2 accepts only the new research profile and phase/role
  vocabulary;
- all required participant, target-distinctness, phase-order, model-call,
  broker-action, byte, cost, and wall-time constraints fail closed;
- GigAI-generated public briefs exclude private/local-only inputs, while every
  participant-supplied ID, URL, citation, result, and claim remains an
  untrusted suggestion until GigAI independently validates and reacquires it;
- unrestricted launches have a fresh execution root and no inherited home,
  `CODEX_HOME`/XDG configuration, worktree, instruction, memory, cache, credential,
  or `PATH`; canary and fake-adapter tests demonstrate that GigAI supplies only
  the sealed public payload and fresh execution root;
- deterministic fixtures prove GigAI's wrapper, while each exact configured
  Codex and Claude adapter separately completes one bounded public marker
  invocation under a disclosure-isolated launch and a proven non-inherited
  authentication channel. Distinct sentinel instructions in every forbidden
  host root must not change the exact marker return; either failure narrows or
  rejects the profile;
- marker-probe tests require a direct operator request and confirmation plus
  an explicit pre-call model-call/token/cost reservation and reconciliation.
  Plan creation, `run-plan show`, and the Run consent preview may inspect a
  proof but never invoke or refresh a marker probe;
- marker-probe schema tests require direct-confirmation evidence, matching
  target/configuration/executable identities, marker digest, reservation,
  actual/reconciled usage, terminal state, timestamps, and stable refusal
  codes; a proof may reference only a matching successful record;
- mutation tests expire or alter the executable digest or authentication
  configuration after consent and immediately before each participant
  invocation; every case fails before prompt assembly/process launch without
  refreshing a proof or spending another provider call;
- consent-preview tests render the exact sealed runtime disclosure, bind it by
  Plan digest to direct confirmation, and reject a missing, changed, or
  participant-mismatched disclosure before Run allocation;
- a broker-generated public evidence view preserves exact broker lineage and
  sanitized policy-approved fields while excluding raw response bytes; a
  subsequent participant receives it only through a new sealed brief and can
  nominate only its exposed opaque result handles;
- the broker rejects forged, impersonated, cross-Run, cross-Plan, malformed,
  stale, duplicate, over-budget, post-cancellation, and unsupported
  suggestions/requests before dispatch;
- reservations occur before dispatch; actual/reconciled accounting, retries,
  timeouts, cancellation, and unknown usage follow the sealed lifecycle;
- every GigAI-started provider invocation and broker event is observable in
  deterministic order without claiming visibility into internal CLI actions;
  and
- the completed S43.3 amendment proves that untrusted participant output cannot
  create authoritative research, evidence, lineage, or consent state.

Stop if a profile can reinterpret v1, an unrestricted participant receives
private/local-only material, a participant-supplied field reaches an
authoritative request/evidence/lineage record without independent GigAI
construction, a broker action is unobserved or unreserved, a role verifies only
itself, or a model can manufacture consent or authority.
