## Current authority-focused gate

The closed-runtime hypothesis below is historical evidence, not the active
acceptance criterion. Its failure remains recorded in `5861c5d` and the linked
decision record; this amendment does not reinterpret that observation.

The current question is whether GigAI can use configured Codex CLI and Claude
Code participants as **untrusted public-research suggestion sources**, while
GigAI alone constructs every authoritative ID, broker request, evidence record,
lineage edge, reservation, and result projection. The authority-focused gate
does not claim that GigAI observes or prevents an unrestricted CLI's internal
turns or native actions. It proves instead that those actions cannot become a
GigAI research action, evidence item, citation, lead, budget entry, or consent
without a separate GigAI-owned broker lifecycle.

Only a disclosure-approved public research brief may enter an unrestricted
participant context. Private references, local-only requirements, résumé text,
private work history, local paths, credentials, prior private artifacts, and
undeclared text remain outside that context and are applied only by GigAI. A
résumé-bearing Tailor Run therefore still requires a separately proven
restricted adapter path.

This is a **disclosure-isolation** gate, not a claim of perfect tool
confinement. Before an unrestricted invocation, GigAI must create an empty,
per-invocation execution root and use it as the process working directory. It
must set `HOME`, `CODEX_HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`,
`XDG_CACHE_HOME`, and `TMPDIR` to fresh empty descendants of that root, pass
only a fixed locale/process allowlist, and invoke a previously resolved
executable by absolute path rather than inheriting `PATH`. The host home,
GigAI home, active worktree, inherited model configuration, agent instructions,
memories, caches, and ambient files must not be process inputs. Authentication,
if a CLI needs it, requires a separately proven adapter channel; inherited
home/XDG configuration is not an authentication channel.

The present `process.py` allowlist inherits `HOME`, `CODEX_HOME`, and XDG
paths, so it cannot satisfy this amended gate. Deterministic fake-adapter
fixtures prove GigAI's wrapper only: deliberate canary instructions/files in
each forbidden host location plus launch inspection must prove that GigAI
supplies only the sealed brief and fresh execution root.

Adopt additionally requires one bounded public marker invocation through each
exact configured Codex CLI and Claude Code adapter, after disclosure isolation
is enabled. Each uses a fixed public prompt containing a fresh non-secret
marker and succeeds only when that adapter returns the exact marker under its
separately proven authentication channel. The same invocation places distinct
sentinel instructions in every forbidden host root; an adapter that follows a
sentinel rather than the fixed marker fails the gate. The evidence records resolved
executable identity/version, adapter identity, safe environment *names*,
execution-root facts, expected/returned marker digests with exact match,
invocation/broker accounting, and the
authentication-channel proof reference—never a credential or host path. An
adapter that needs inherited home/XDG configuration, cannot authenticate through
the isolated channel, or cannot produce the bounded marker yields Narrow or
Reject. The strict proof is
`urn:gigai:schema:participant-authentication-channel-proof:1`; it binds the
target/adapter/channel plus resolved executable digest/version, a non-secret
authentication-channel configuration reference/digest, sets
`home_xdg_inheritance: false`, and expires. A later v2 Plan binds its own
participant ID to the proof; the probe itself is not participant-specific. Its
`marker_evidence` is a matching successful
`urn:gigai:schema:marker-probe-record:1` record, which contains direct
confirmation evidence, target/configuration/executable identities, marker
digests with exact match, reservation, actual/reconciled usage, terminal state,
timestamps, and stable refusal codes without retaining a credential, raw
prompt, marker, or provider output. Direct confirmation binds the local
operator actor and terminal session; absent confirmation returns its stable
diagnostic without allocating a probe record.

The marker probe is one provider call, not an Exa call or research Run. It may
run only through direct operator command
`gigai models --probe TARGET --s43-public-marker --max-tokens N --max-cost-usd C --confirm`.
GigAI generates the marker after confirmation, reserves the declared finite
model-call/token/cost limits before invocation, records actual/reconciled usage,
and records only the schema's valid terminal state/code pair. Missing direct
confirmation and non-positive, non-finite, or unreservable limits refuse before
probe-ID/reservation/record creation with their stable CLI diagnostics. Plan
construction, Plan display, and Run-consent preview may read a current proof
but must never probe, refresh, or spend provider budget implicitly.
Immediately before every later participant invocation, GigAI must revalidate
the proof's target/adapter executable digest, current channel-configuration
digest, successful marker record, and expiry. Any post-consent mismatch fails
before prompt assembly and never triggers an implicit probe or refresh.

It does not claim that an unrestricted native tool could never discover another
host path; any such native activity remains unobserved and non-authoritative
under the narrower authority boundary.

## Historical closed-runtime question

Can the configured Codex CLI and Claude Code adapters run as authenticated,
observable participants with no research path except a GigAI-owned local broker?

The required boundary is stronger than disabling a nominal network flag. An
adapter must prevent its participant from using shell, browser, native tools,
ambient credentials, provider-native web/search tools, alternate local sockets,
or direct network access to bypass the broker. If either adapter cannot provide
that boundary, this spike must Narrow or Reject; prompt instructions do not
count as enforcement.

## Historical candidate execution shape

```text
sealed Run Plan + direct Run consent
  -> one capability-reduced participant process per assigned role
       -> that participant's authenticated local broker channel only
            -> GigAI validates, reserves, dispatches, reconciles, records
                 one reviewed provider action
```

Each participant receives an ephemeral, role-bound broker channel. It can ask
only for actions named by the sealed Plan. The broker channel is not shared
between participants and cannot select a different Run, Plan, role, provider,
or capability. No Exa credential or other research credential is supplied to a
participant process, prompt, environment, workpad artifact, or diagnostic.

## Historical required feasibility evidence

S43.3 must test both adapters under the candidate boundary and retain only
sanitized evidence. It must establish all of the following:

1. **Closed capability surface.** Shell execution, browser automation, native
   provider tools, arbitrary network access, alternate local IPC, ambient
   credential reads, and direct provider requests are absent or fail closed.
   The evidence names the actual adapter/sandbox flags and OS-level boundary;
   it does not infer closure from a system prompt.
2. **Broker-only authenticated actions.** A valid participant can submit one
   typed request through its own ephemeral channel. A forged, replayed,
   malformed, cross-participant, cross-Run, cross-Plan, or post-cancellation
   request is refused before provider dispatch.
3. **Complete observability.** Every model turn, broker request, reservation,
   dispatch attempt, response, reconciliation, retry decision, timeout, and
   cancellation has a durable Run-scoped event with a stable sequence number.
   The test may redact content but cannot omit a call from accounting.
4. **Bounded lifecycle.** Requests execute serially unless a later approved
   profile declares a concurrency limit. A cancellation while a provider call
   is in flight has one terminal reconciliation event and no subsequent action.
   Retrying the same idempotency key returns its recorded outcome without a
   second provider call; a new attempt consumes a new sealed reservation.
5. **Fail-closed adapter behavior.** Adapter crash, timeout, malformed tool
   result, unknown provider usage, unobservable native tool call, or failure to
   prove a denied bypass leaves the Run blocked or failed. It never silently
   falls back to a less-restricted adapter or local direct access.

The spike must explicitly record whether the current Codex and Claude adapters
meet the boundary independently. “One adapter works” is a Narrow result, not an
Adopt result for a two-participant research profile.

## Historical decision record

The evidence chooses exactly one decision:

- **Adopt:** both adapters meet every required boundary. The record identifies
  their immutable adapter/version facts, the capability-reduction method,
  broker authentication/channel design, observed-event mapping, cancellation
  behavior, and fixture/replay strategy.
- **Narrow:** state which adapter or capability is unsupported and define the
  smaller safe profile that could be contracted later. Do not label it a
  Codex-plus-Claude independent-research profile.
- **Reject:** neither reviewed adapter can meet the closed capability boundary.
  Leave G43.3, G45.2, and G46.2 inactive; do not emulate the broker with agent
  instructions, a shared API key, or an unconfined CLI subprocess.

## Historical out of scope and stop conditions

S43.3 does not call Exa with live data, create a Run Plan schema, add a
credential, implement a broker, or change G43 `standard@1`. It tests runtime
feasibility only with deterministic fake-provider/broker fixtures.

Stop with Narrow or Reject if a participant can access a bypass surface, can
impersonate another participant, produces an unobservable model/tool action,
cannot be cancelled/accounted deterministically, or requires a secret in the
agent-visible environment. No downstream implementation may treat an
inconclusive result as authority.

## Historical decision

S43.3 is complete with a **Reject** decision. The current Codex CLI adapter
retains a model-available shell surface and user configuration, while the
current Claude Code adapter has neither an authenticated GigAI broker channel
nor per-turn/per-tool lifecycle evidence. Neither is the required closed
participant runtime, so this spike does not unblock G43.3. The evidence record
identifies the exact local versions, static adapter facts, and the non-provider
shell-surface probe.
