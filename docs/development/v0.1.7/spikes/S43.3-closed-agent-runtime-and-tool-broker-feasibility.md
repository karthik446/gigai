# S43.3 — Closed Agent Runtime and Tool-Broker Feasibility

**Version:** v0.1.7
**Status:** Proposed research gate — not implementation authority
**Depends on:** G40 runtime invocation boundary and completed G43
**Unblocks:** G43.3 only on an Adopt decision

## Question

Can the configured Codex CLI and Claude Code adapters run as authenticated,
observable participants with no research path except a GigAI-owned local broker?

The required boundary is stronger than disabling a nominal network flag. An
adapter must prevent its participant from using shell, browser, native tools,
ambient credentials, provider-native web/search tools, alternate local sockets,
or direct network access to bypass the broker. If either adapter cannot provide
that boundary, this spike must Narrow or Reject; prompt instructions do not
count as enforcement.

## Candidate execution shape

```text
sealed Run Plan + direct Run consent
  -> one capability-reduced participant process per assigned role
       -> that participant's authenticated local broker channel only
            -> GigAI validates, reserves, dispatches, reconciles, records
                 one reviewed provider action
```

Each participant receives an ephemeral, role-bound broker channel. It can ask
only for actions named by the sealed Plan. The broker channel is not shared
between participants and cannot select a different Run, Plan, role, provider,
or capability. No Exa credential or other research credential is supplied to a
participant process, prompt, environment, workpad artifact, or diagnostic.

## Required feasibility evidence

S43.3 must test both adapters under the candidate boundary and retain only
sanitized evidence. It must establish all of the following:

1. **Closed capability surface.** Shell execution, browser automation, native
   provider tools, arbitrary network access, alternate local IPC, ambient
   credential reads, and direct provider requests are absent or fail closed.
   The evidence names the actual adapter/sandbox flags and OS-level boundary;
   it does not infer closure from a system prompt.
2. **Broker-only authenticated actions.** A valid participant can submit one
   typed request through its own ephemeral channel. A forged, replayed,
   malformed, cross-participant, cross-Run, cross-Plan, or post-cancellation
   request is refused before provider dispatch.
3. **Complete observability.** Every model turn, broker request, reservation,
   dispatch attempt, response, reconciliation, retry decision, timeout, and
   cancellation has a durable Run-scoped event with a stable sequence number.
   The test may redact content but cannot omit a call from accounting.
4. **Bounded lifecycle.** Requests execute serially unless a later approved
   profile declares a concurrency limit. A cancellation while a provider call
   is in flight has one terminal reconciliation event and no subsequent action.
   Retrying the same idempotency key returns its recorded outcome without a
   second provider call; a new attempt consumes a new sealed reservation.
5. **Fail-closed adapter behavior.** Adapter crash, timeout, malformed tool
   result, unknown provider usage, unobservable native tool call, or failure to
   prove a denied bypass leaves the Run blocked or failed. It never silently
   falls back to a less-restricted adapter or local direct access.

The spike must explicitly record whether the current Codex and Claude adapters
meet the boundary independently. “One adapter works” is a Narrow result, not an
Adopt result for a two-participant research profile.

## Decision record

The evidence chooses exactly one decision:

- **Adopt:** both adapters meet every required boundary. The record identifies
  their immutable adapter/version facts, the capability-reduction method,
  broker authentication/channel design, observed-event mapping, cancellation
  behavior, and fixture/replay strategy.
- **Narrow:** state which adapter or capability is unsupported and define the
  smaller safe profile that could be contracted later. Do not label it a
  Codex-plus-Claude independent-research profile.
- **Reject:** neither reviewed adapter can meet the closed capability boundary.
  Leave G43.3, G45.2, and G46.2 inactive; do not emulate the broker with agent
  instructions, a shared API key, or an unconfined CLI subprocess.

## Out of scope and stop conditions

S43.3 does not call Exa with live data, create a Run Plan schema, add a
credential, implement a broker, or change G43 `standard@1`. It tests runtime
feasibility only with deterministic fake-provider/broker fixtures.

Stop with Narrow or Reject if a participant can access a bypass surface, can
impersonate another participant, produces an unobservable model/tool action,
cannot be cancelled/accounted deterministically, or requires a secret in the
agent-visible environment. No downstream implementation may treat an
inconclusive result as authority.
