# S45.2 — Public Structured Job-Source Access

**Version:** v0.1.7
**Status:** Proposed research gate — not implementation authority
**Depends on:** G46.1 Tailor v1 contract and implementation evidence
**Unblocks:** G45.2 only if the decision is Adopt

## Question

Can GigAI support one operator-configured, unauthenticated, public, structured
job-source class through one reviewed source adapter without browser automation,
credentials, generic crawling, or a privacy/authority bypass?

## Research boundary

The spike is read-only research. It does not implement an adapter, fetch live
job results through GigAI, add credentials/cookies, create a source registry,
or activate G45.2. It evaluates a small number of candidate public APIs, feeds,
or ATS endpoints for published access terms, structured response shape, stable
identity fields, rate limits, origin/redirect behavior, and fixture feasibility.

It rejects as out of scope: arbitrary URLs, HTML scraping, browser sessions,
JavaScript execution, login, CAPTCHA handling, search-engine fallback, model
directed fetching, and claims of comprehensive market coverage.

## Required decision record

The evidence record must choose exactly one outcome:

- **Adopt:** name one source class and one adapter boundary, record accepted
  terms/rate limits, allowed HTTPS origins and URL shapes, query fields,
  response ceilings, lead identity/provenance fields, and deterministic
  fixture/replay plan;
- **Narrow:** identify the missing condition and an even smaller source class
  that could be reconsidered; or
- **Reject:** state why no acceptable first source exists and leave G45.2
  inactive.

It may not recommend a source merely because it can be scraped. The decision
must show that an explicit outbound query can exclude résumé text, private work
history, credentials, cookies, and surrounding conversation by construction.

## Acceptance and stop conditions

Adopt requires a source-specific policy that can be expressed as a closed
registry entry and exercised with sanitized fixtures: origin allowlist,
redirect policy, HTTPS-only transport, terms/rate rule, bounded request and
response behavior, normalized lead identity, and raw/normalized provenance.

Stop with Narrow or Reject if the source needs login/cookies/browser execution,
has unacceptable terms, cannot supply a stable structured lead identity, cannot
be bounded against SSRF/private-network access, or cannot be replayed from a
sanitized fixture. No implementation may proceed on an unresolved source.
