# S45.2 — Exa-Backed Job Research Capability

**Version:** v0.1.7
**Status:** Proposed research gate — not implementation authority
**Depends on:** G46.1 Tailor v1 contract and implementation evidence
**Unblocks:** G45.2 only if the decision is Adopt

## Question

Can GigAI use the operator's configured Exa access as a bounded research tool
for Codex and Claude, while preserving direct Run consent, query privacy,
provider accounting, source provenance, and no-unattended-work boundaries?

## Research boundary

The spike is read-only research. It does not add an Exa credential, call Exa
through GigAI, implement a tool runner, or activate G45.2. It verifies Exa's
current API/terms, available search/content action shapes, attribution and
retention expectations, usage/cost accounting, response limits, result/citation
fields, and whether those controls can be represented as a sealed policy plus
sanitized replay fixtures.

The target design is deliberately narrow: a configured Exa credential reference
in machine configuration; only mediated `search` and `contents` actions; a
direct-confirmed foreground Run; and Codex/Claude requests validated against a
sealed budget. It rejects direct arbitrary URL fetches, browser sessions,
JavaScript, login, cookies, generic web search outside Exa, model-supplied
network endpoints, and claims of complete job-market coverage.

## Required decision record

The evidence record must choose exactly one outcome:

- **Adopt:** name the Exa API/capability version, credential-reference
  configuration boundary, permitted action types, query-field mapping,
  per-Run ceilings, usage/cost rule, citation/snapshot fields, fixture/replay
  plan, and provider-failure behavior;
- **Narrow:** identify the missing condition and a smaller mediated Exa action
  set that could be reconsidered; or
- **Reject:** state why Exa cannot satisfy the required privacy, accounting,
  provenance, or bounded-execution contract and leave G45.2 inactive.

It may not use a model's ability to browse as evidence that GigAI can grant a
generic browsing capability. The decision must show that the outbound Exa
request excludes résumé text, private work history, credentials, cookies, and
surrounding conversation by construction.

## Acceptance and stop conditions

Adopt requires an exact policy expressible as
`urn:gigai:schema:exa-research-policy:1`, with a bounded action set, role-level
and Run-level limits, machine-local credential reference, usage/cost accounting,
source/citation provenance, privacy-safe query mapping, and deterministic
sanitized fixture/replay material.

Stop with Narrow or Reject if Exa cannot use a configured non-secret reference,
cannot return usable citation/provenance data, lacks bounded/recordable
usage/cost, requires unsanctioned browser or login behavior, or cannot be
replayed from sanitized fixtures. No implementation may proceed on an
unresolved capability.
