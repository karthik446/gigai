## 4. Operator rules learned this release (all in Claude memory; most in the skill)

- **Hand off; don't do.** Debugging, CI audits, fixes and long test lanes go to workers with specs; the coordinator verifies and reports.
- **The coordinator reviews content itself** (roadmaps, tickets, spikes, contracts), walking every consumer. Mechanical checks and Terra are extra, not a substitute.
- **Test budget:** workers run only the tests for the files they changed. The full `make test` runs once per release, by the coordinator, in one TEST tab (the Mac spins).
- **Close workers:** `sweep_workers.py` (run by `wait.sh` every 5 min) releases settled workers idle ≥ 5 min **and closes their tabs** (`worker-release` alone leaves Claude tabs open). Never touch terminals the Run didn't start.
- **Architecture rule:** a Gig (Scout; later trader, shopper) imports core; **core never imports a gig.** Never phrase it as "may".
- **Discussions aren't decisions.** Don't write ideas or discussions into `decisions.log` or `status.md` as decisions; put them in a spike or doc.
- **macOS gates releases** ("everyone uses macOS"). CI profiles: `pr` (ubuntu 3.11) · `release` (macOS 3.12 + ubuntu 3.12, blocking) · `full` (3×3 + Debian; nightly + post-release).
- **Never deploy by default**, but the operator can explicitly ask for the tag push (they did for v0.1.8).
- **Secrets:** `.orchestrator/` is committed. Scan it for `dcap_…`, keys and the operator's email before every commit, and redact.
