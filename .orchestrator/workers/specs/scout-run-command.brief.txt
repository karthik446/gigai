ADDENDUM (0.1.8.1 UAT, 2026-09-24):
- A NON-GIT target (`gigai init --target ~/scout`) has no <target>/.gigai/project.toml. The active gig lives only in the registry. The U14 workaround (append active_gig_id to project.toml) can't work there; it took calling workpad.select_active_workpad from Python. `gigai scout run` must set the active gig for both git and non-git targets.
- U2 is still in 0.1.8.1: setup names targets codex-default/claude-default, and find-jobs resolves the literal name "codex_cli" (scout/proposal_execution.py:117-125). Workaround: `gigai setup --non-interactive --model-target "codex_cli=codex:default"`.
- A missing find-jobs.json → the API returns 404 on /api/config, and the UI shows "Could not load configuration: That run could not be found". Wrong message: it should say the config is missing and offer to create it. `gigai scout run` should create a starter config.
- Exa failure hidden: the run recorded only `exaclienterror: Exa search failed`. The real cause was HTTP 402 (no key sent): ~/.gigai/.env had the key under EXA_SECRET_KEY, EXA_API_KEY was empty, and exa_client reads only EXA_API_KEY. Record the HTTP status + a redacted reason (e.g. exa_missing_key / exa_http_402), and check for the key before the run starts. Feeds roadmap workstream 0 (`gigai secrets add exa` writes the right name). Also, a fresh install has an empty ATS watchlist, so an Exa failure means 0 postings while the run still shows "succeeded". Consider marking the run degraded or failed when every source fails.
